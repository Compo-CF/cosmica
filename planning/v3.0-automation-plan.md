# Cosmica 3.0 — The Automation Update

**Status:** planning locked, code work starts once v2.1.1 (build 18) approves and is live.
**Decision date:** 2026-09-16
**Codename:** "Automation"
**Target ship:** ~3 weeks after v2.1.1 approves (per-phase estimates below)

## Why 3.0

- Idle-game players expect automation. Cosmica currently has none — every late-game session is tap-heavy despite being marketed as "idle"
- Automation Core is one of the highest-conversion IAP product types in this genre (Cookie Clicker, Antimatter Dimensions, Trimps all sell exactly this SKU)
- Notifications + a home-screen widget together change the daily-open pattern from "opens because they remember" to "opens because the app pinged them / because they saw a stardust number climbing on their home screen"
- Ships as a real 3.0 update banner in the App Store — meaningful behavior change, not just more numbers

## Non-goals for 3.0

Deliberately out of scope, deferred to 3.1 or later:

- **Third prestige layer past True Cosmos** (Void Sparks / Multiverse Collapse) — 3.1
- **Cosmetics IAP surface** (alternate orbs, themes, name plates) — 3.2
- **New Cosmic Wonders** — 3.1 slot expansion goes with Multiverse
- **New generators or tiers** — save for a 3.3 content update if organic growth demands it

## What ships in 3.0

Six phases. Each is a coherent commit train; each can theoretically ship to TestFlight standalone if we needed to split.

### Phase 1 — Foundation & IAP (~4h)

**Files touched:** `IAPManager.swift`, `Services/AutomationManager.swift` (NEW), `GameState.swift`, `SettingsView.swift`, `ShopView.swift` maybe.

**Deliverables:**
- New product ID: `automation_core`, non-consumable, $2.99 (Tier 3)
- `IAPManager.automationCoreOwned: Bool` published observable
- `AutomationManager` service (`@Observable`) holding the runtime automation state
- `GameState.automationTrialExpiresAt: Date?` (Codable, decodeIfPresent for save compat)
- Rewarded-ad callback in `ShopView` can call `AutomationManager.grantTrial(hours: 4)` — writes trial date
- Computed property `AutomationManager.isActive: Bool` — true if `automationCoreOwned || trialExpiresAt > now`
- Settings → Purchases row: "Automation Core — Owned / Trial (2h 45m left) / Not owned"

**Ships as a no-op until Phase 2.** Player owns/trials it but nothing yet actually automates.

**Anthony blockers:**
- Create `automation_core` IAP in App Store Connect (5 min guided)
- Draft IAP description (I'll provide — see metadata section below)

### Phase 2 — Auto-buy generators (~6h)

**Files touched:** `CosmicTree.swift`, `GameEngine.tick()`, `GeneratorRow.swift`, `Autonomy*.swift` (NEW branch of tree), `AutomationManager.swift`.

**Deliverables:**
- New Cosmic Shard tree branch: **Autonomy** (3 nodes)
  - `autonomy_reactor` — 25 shards — unlocks auto-buy on generators 1-3 (Stellar Nursery through Neutron Forge)
  - `autonomy_nexus` — 100 shards — unlocks auto-buy on generators 4-6 (Quasar Array through Void Engine)
  - `autonomy_absolute` — 500 shards — unlocks auto-buy on generators 7-8 + all future
- Per-generator toggle button in `GeneratorRow` — small button. Only visible if that generator's auto-buy is unlocked. Persists per-generator flag in state
- New state field: `GameState.autoBuyEnabled: [String: Bool]` keyed by generator id
- On each engine tick (30 Hz), if `AutomationManager.isActive` && a per-generator toggle is on && generator is unlocked, run the strategy
- Strategy: **Cheapest** — buy the single cheapest-affordable generator this tick. Never spends more than 50% of current stardust in one tick (avoids draining pre-Big-Bang)
- New Settings row (only if Core owned): "Auto-buy strategy" (Cheapest / Balanced / Highest — Cheapest default)

**Highest player-felt impact of the whole release. This is the phase people will describe when they tell a friend.**

### Phase 3 — Auto-prestige (~4h)

**Files touched:** `BigBangView.swift`, `GameEngine.swift`, `AutomationManager.swift`.

**Deliverables:**
- New Big Bang tab section (only visible if `AutomationManager.isActive`): **Auto-Big-Bang**
- Toggle: "Enable Auto-Big-Bang"
- Threshold picker (Segmented control or Menu): **10 / 100 / 1K / 10K / 100K / 1M shards**
- When auto-firing: skip the confirmation dialog, still play the confetti + haptic
- Auto-fire path DOES NOT trigger the `BoostNudgeSheet` (respect user's active session — that sheet requires their attention, and if they're not actively watching, the sheet just sits there uselessly)
- Auto-fire path DOES fire GameCenter score updates + achievement checks (unchanged from manual bigBang())
- `state.lastAutoBangAt: Date?` — used to rate-limit and diagnose
- If Big Bang fires while app is backgrounded, no notification fires (avoid annoying)

### Phase 4 — Auto-collect events + auto-Cosmic-Tree (~3h)

**Files touched:** `CosmicEventScheduler.swift`, `SettingsView.swift`, `CosmicTree.swift`, `AutomationManager.swift`.

**Deliverables:**
- Two new toggles in Settings (only if Core owned):
  - "Auto-collect cosmic events" — event auto-collects on spawn tick, no notification
  - "Auto-buy Cosmic Tree upgrades" — after each Big Bang (manual OR auto), spends banked shards on the cheapest available Cosmic Tree node
- Auto-tree-buy explicitly **skips the Autonomy branch itself** (don't want autonomy buying its own successor nodes with the shards the player is trying to save for something they picked)
- Auto-tree-buy stops when no node is affordable OR when the player has more than 100 shards banked (so they can still make a targeted purchase without wrestling the automator for it)

This closes the automation surface. Player literally cannot miss a passive gain after this.

### Phase 5 — Push notifications (~5h — first time for Cosmica)

**Files touched:** `Info.plist` (via project.yml), `AppDelegate.swift`, `NotificationManager.swift` (NEW), `OnboardingView.swift`, `SettingsView.swift`, `GameEngine.swift` (schedule triggers).

**Deliverables:**
- New service: `NotificationManager` — wraps `UNUserNotificationCenter`
- Permission requested from a Settings toggle, NOT during onboarding (already too much friction there with ATT). Onboarding gets a hint: "Turn on notifications in Settings for cosmic event alerts."
- Notification types (all local, no APNs, no server):
  - "Your reactor is ready to Big Bang" — scheduled when `availableShards` computed rate crosses each 10x threshold since last Big Bang. Never fires more than once per hour
  - "Cosmic event active" — fires when a rare event spawns AND auto-collect is off
  - "Daily reward available" — fires 26h after last claim
- All notifications deep-link into the app (Big Bang tab, Observatory tab, Shop tab respectively) via `UNNotificationResponse.actionIdentifier`
- Settings row: master toggle + per-type toggle (3 subs)
- `Info.plist` addition (via project.yml): none required for local notifications — permission is prompted at API call time

### Phase 6 — iOS home-screen widget (~8h — biggest first-time-effort in the plan)

**Files touched:** `project.yml` (new target `CosmicaWidget`), `CosmicaWidget/CosmicaWidget.swift` (NEW), `CosmicaWidget/Timeline.swift` (NEW), `Cosmica/Services/WidgetSnapshotWriter.swift` (NEW), `GameEngine.swift` (call snapshot writer every 30s), `.entitlements` for App Group.

**Deliverables:**
- New Xcode target: `CosmicaWidget` — a WidgetKit extension
- Two widget sizes:
  - **Small (systemSmall)** — stardust/sec + prestige count + tier badge
  - **Medium (systemMedium)** — all of small + progress bar toward next shard + current shard count
- App Group entitlement: `group.com.centricfiber.cosmica` — shared between app and widget
- Every 30 sec (throttled), `WidgetSnapshotWriter` writes latest engine state to shared UserDefaults
- Widget timeline provider reads shared UserDefaults every 15 min (iOS-imposed widget refresh cap)
- Widget tap → deep-link into Observatory tab

**Ships last** — biggest scope, most net-new APIs (WidgetKit + App Groups + Timeline entries), and if it slips it's the easiest thing to hold for 3.0.1.

## What could rejection-block us

Two risks worth naming now so we don't hit them at submit:

1. **Automation Core IAP description must be crystal-clear about what it grants**. Apple gets prickly about "you're paying for something the app should do." Frame it as an *unlock* (which it is): "Unlock Automation — buy 8 generators, prestige, collect events, and spend Cosmic Shards on the Cosmic Tree without tapping." Doesn't say "premium," doesn't imply the free game is limited.
2. **Rewarded-ad-for-4h-trial** must not be labeled as "unlocking a paid feature for watching an ad" in a way that reads as pay-wall-bypass. Frame it as: "Try Automation for 4 hours" — a demo, not a discount. This has shipped in dozens of idle games, it's fine, but the copy matters.
